# Firm Size Distribution and Power Laws in Brazil

Replication package for:

> Marcelo Resende and Vicente Cardoso. **Firm Size Distribution and Power Laws
> in Brazil: Empirical Evidence.**

The paper tests power-law behaviour in the Brazilian firm size distribution
using the annual ranking of the 1,000 largest companies by net revenue,
fiscal years 1999–2024. A nested testing strategy is applied to the top
1,000, 500 and 100 firms: Pareto type I within Pareto type II (LMp), Zipf
within Pareto type II (LMz), and Pareto type I against Pareto type IV (PWL).
The evidence favours a Pareto type I tail only for the top 100 firms,
whose exponent falls from about 1.27 in 1999–2009 to about 1.05 in 2010–2024,
with a structural break in 2010.

This repository contains the final manuscript, the source data, the complete
analysis code and every output reported in the paper.

## Data

The panel combines the IBRE-FGV series of the largest firms (fiscal 1999–2000,
published in *Conjuntura Econômica*) with the annual ranking of the 1,000
largest Brazilian companies by net revenue published by *Valor Econômico*
(fiscal 2001–2024, the "Valor 1000" yearbook). The workbooks in `data/raw`
compile those rankings into a consistent fiscal-year panel; their sheets are
named by edition year, so sheet `YYYY` reports fiscal year `YYYY − 1`. See
[`data/README.md`](data/README.md) for the file-by-file description, the two
documented repairs and the SHA-256 checksums.

The cleaned panel is produced by the code and written to
`output/cleaned_panel.csv`: 26 annual cross-sections of exactly 1,000 firms
(26,000 rows), with fiscal year, rank, company name, a normalised name for
cross-year matching, and revenue in R$ million.

## Running the replication

```bash
python code/run.py       # rebuild every table, the figure and the panel
python code/verify.py    # compare the outputs with the printed tables
```

`make all` runs both. The pipeline takes about two minutes on a laptop; most
of the time is spent in the bootstrap loops of Tables 1–3 and 5.

`code/run.py` writes:

| File | Contents |
|---|---|
| `output/cleaned_panel.csv` | cleaned 26,000-row panel used in all estimates |
| `output/tables/table_1.csv` | top 1,000: LMp and LMz tests, asymptotic and bootstrap p-values |
| `output/tables/table_2.csv` | top 500: same tests |
| `output/tables/table_3.csv` | top 100: same tests |
| `output/tables/table_4.csv` | cutoff grid: rejection counts and Hill exponents |
| `output/tables/table_5.csv` | Pareto type I against Pareto type IV, top 100 |
| `output/tables/table_6.csv` | Hill and OLS-Gabaix–Ibragimov estimates, Zipf tests |
| `output/trend_break.csv` | Mann–Kendall, Theil–Sen, sup-Wald and Pettitt statistics |
| `output/figure1.png`, `.pdf` | Figure 1: top-100 exponent, trend and break |
| `output/manifest.json` | versions, seeds, replication counts and source checksums |

The generated tables carry full precision and a few extra columns (sample
size, standard errors, cutoffs) that the printed tables omit.

## Reproducibility

All random draws use fixed seeds recorded in `output/manifest.json`:

| Purpose | Seed | Replications |
|---|---|---|
| Tables 1–3, LMp and PWL stream | 20260701 | 999 |
| Tables 1–3, LMz stream | 20260702 | 999 |
| Table 5, PWL test | 20260923 + fiscal year | 19,999 |
| Table 6, Zipf bootstrap | 20260908 | 20,000 |
| Trend/break bootstrap | 20260908 (continuation) | 20,000 |

The bootstrap p-values in Tables 1–3 use the fixed 999-replication
calibration sample described in the code (`historical_bootstrap` in
`code/tables.py`); point estimates and asymptotic p-values use the full
cleaned panel. The two RNG streams are consumed in the same order as in the
original calibration, including the PWL draws that Tables 1–3 do not report.

`code/verify.py` checks the source checksums, the panel structure, all six
tables, the trend/break statistics and the figure. Printed values are compared
at their three-decimal precision: half a unit in the last digit (0.0005) for
coefficients and test statistics, one unit (0.001) for p-values, which carry
optimizer and simulation noise at that order. The Table 6 OLS-GI bootstrap
column is a separate simulation and is checked with a 0.005 tolerance.
